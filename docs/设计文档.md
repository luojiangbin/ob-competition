# 设计文档 · 课程项目上下文接力（Course Context Relay）

> 参赛方向：PowerContext ｜ 队伍：10086 ｜ 作者：罗江斌（宜宾学院）
> 状态：v1（初赛阶段），已实现部分标注为「已实现」，其余标注为「规划」

---

## 1. 问题

一个大二学生一学期同时上 5–6 门课，每门课一个课设。真实发生的事：

1. **会话断裂**：上周和 AI 敲定的架构，这周开新会话，要从头解释一遍。
2. **交接断裂**：队友接手你的课设，你得把"老师的要求、已定的选型、踩过的坑"重新讲一遍。
3. **工具断裂**：换一个 Agent、换一台电脑，上下文带不过去。

现有做法都不解决根本问题：

| 做法 | 为什么不够 |
|---|---|
| 重读聊天记录 | 上下文窗口有限，且跨会话不存在 |
| RAG 聊天记录 | 检索到的是原话碎片，不是"结论" |
| 本地 memory 文件 | 绑在单个 Agent 上，换工具就失效 |
| 让人复述 | 成本最高，且会遗漏 |

**核心矛盾**：课设真正需要延续的是**决策、约束、进度**，而不是聊天文本。

## 2. 方案

### 2.1 映射关系

把"一门课设"映射成一个 **Scope**，四类上下文分别落到 PowerContext 的原语：

| 学生场景 | 原语 | 生命周期 |
|---|---|---|
| 一门课 = 一个隔离空间 | Scope | 整学期 |
| "老师要求 C++17，禁用第三方库" | Memory（constraint） | 长期有效，跨会话 |
| "为什么选 DFS 不选 BFS" | Memory（decision） | 长期有效 |
| "pop_back 那个坑" | Memory（pitfall） | 长期有效，避免重犯 |
| 队友接手 | Handoff（规划） | 一次性交接 |
| "这个坑我踩过" 的可复用经验 | Experience（规划） | 审核后复用 |

### 2.2 召回链路

```
学生提问
  → 查询改写（同义词扩展，规则表）
  → /v1/context/prepare（Scope 内检索 + 字节预算）
  → 返回有界历史上下文
  → 拼进模型请求的 system message
```

两个关键设计：

1. **写入时改写**：记忆不写"当时的说法"，写"未来会怎么问"。
   - 反例：`禁止使用 ORM`
   - 正例：`课设不允许使用 ORM，必须手写 SQL`
2. **查询时扩展**：口语 → 术语（深搜→DFS、进程控制块→PCB），纯规则、零成本、可审计。

### 2.3 为什么不用"全量塞进去"

- 上下文有预算，塞多了稀释注意力；
- 无关记忆会误导模型（历史内容不是指令）；
- `prepare` 的字节预算强制我们做**选择**，而选择本身就是检索质量。

## 3. 实验

四组对照，判定方式为"上下文是否命中期望关键词"，确定性、可复现：

| 组 | 条件 | 准确率 |
|---|---|---|
| A | 自然写法 | 80% |
| B | 写入改写 | 100% |
| C | 留出集（未调优） | 100% |
| D | 同义词集（刻意换词） | **10%** |
| E | 同义词集 + 查询改写 | 90% |

详细失败样例与复现命令见 [实验报告.md](./实验报告.md)。

**结论**：纯字面检索的天花板在语义层。写入改写与查询扩展是低成本补丁，真正的解是向量/混合检索——这正是 PowerContext 配置 Embedding 后的能力路径。

---

## 4. 边界与失败分析

| 场景 | 现状 | 原因 |
|---|---|---|
| 同义词、口语化提问 | 10%（无扩展）/ 90%（有扩展） | FTS 无语义 |
| 跨语言（中问英记） | 基本失效 | 分词器不跨语言 |
| 记忆过多时的排序 | 未验证 | 未做大规模压测 |
| 多轮修订同一决策 | 未实现 | Memory 目前只增不改 |
| 队友交接 | 未实现 | Handoff 待接入 |

**我们明确不声称**：这套方案能处理开放域问答；它只针对"课程项目"这个封闭域。
