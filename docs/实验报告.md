# 召回实验报告 v1

> 实验环境：PowerContext 1.4.0，SQLite，本地单机，Basic memory（无模型 API）
> 数据：5 个课设 Scope，25 条记忆
> 判定：`/v1/context/prepare` 返回的上下文是否命中期望关键词（确定性判定，不依赖模型）

---

## 一、四组结果

| 组 | 用例集 | 记忆写法 | 查询改写 | 准确率 |
|---|---|---|---|---|
| A | 开发集 20 题 | 自然表述 | 否 | **16/20 = 80%** |
| B | 开发集 20 题 | 面向提问改写 | 否 | **20/20 = 100%** |
| C | 留出集 10 题（未参与调优） | 面向提问改写 | 否 | **10/10 = 100%** |
| D | 同义词集 10 题（刻意换词） | 面向提问改写 | 否 | **1/10 = 10%** |
| E | 同义词集 10 题 | 面向提问改写 | 是 | **9/10 = 90%** |

回归检查：开发集在开启查询改写后仍为 20/20，无退化。

---

## 二、失败模式

### A 组（80%）——记忆措辞与提问措辞不一致

| 提问 | 记忆原文 | 结果 |
|---|---|---|
| 课设**允许**用 ORM 吗？ | **禁止**使用 ORM | 未召回 |
| 能用 Flask 吗？ | **禁止使用任何 Web 框架** | 未召回 |
| pop_back 那个 bug | 用 vector 当栈时 pop_back() 不返回**被删元素** | 未召回 |

结论：全文检索是**字面匹配**，`允许` vs `禁止`、`Flask` vs `Web 框架`，一个字对不上就整条漏掉。

### D 组（10%）——同义词/口语化

| 提问 | 记忆里的术语 | 结果 |
|---|---|---|
| 为什么用**深搜**而不是**广搜**？ | DFS / BFS | 未召回 |
| **进程控制块**是怎么存的？ | PCB / 结构体数组 | 未召回 |
| 进程一直**跑不完**？ | 时间片为 0 导致死循环 | 未召回 |

结论：这是纯 FTS 的**真实天花板**——用户不会背你的术语表。

### E 组（90%）——查询改写能补多少

规则表把口语词扩成术语（深搜→DFS、进程控制块→PCB），同义词集从 10% 提到 90%。

但代价明确：

- 同义词表**领域相关**，换一门课就要重新维护
- 只能覆盖**预想到的**说法，遇到新说法仍然漏
- 表越大，误召回风险越高

## 三、规模测试：记忆变多会不会变差

场景：一个 Scope 里逐步堆到 400 条记忆，其中 10 条是"目标记忆"，问 10 个只有目标能回答的问题。

| 记忆总数 | 命中 | p50 延迟 | p95 延迟 |
|---|---|---|---|
| 25 | 10/10 | 29.2 ms | 42.2 ms |
| 100 | 10/10 | 32.1 ms | 85.6 ms |
| 200 | 10/10 | 38.7 ms | 83.3 ms |
| 400 | 10/10 | 30.9 ms | 82.1 ms |

结论：

- **召回不随规模下降**：400 条干扰项没有淹没 10 条目标，命中率稳定 10/10。
- **p50 稳定在 30–40 ms**，p95 从 42 ms 升到 82 ms 后走平——排序成本有上限，不是线性恶化。
- 这只证明**课堂规模**（几百条）没问题，不能外推到几万条；更大规模需要索引与向量检索，未测。

> 方法学备注：第一次跑出 4/10 是**判定脚本的错**——我拿 `mysql8`、`rr-zero` 这类英文代号当命中关键词，而记忆里写的是 `MySQL 8.0`、`时间片`，文本里根本没有这些串。
> 换成真实出现的词后立刻 10/10。这件事本身又是一次印证：**关键词必须真的出现在记忆文本里，否则测的是脚本不是系统。**

## 四、对方案的启示

1. **写入时改写**是零成本收益：记忆必须写成"未来提问的样子"，而不是"当时的说法"。
2. **查询时改写**是低成本补丁：适合课程域这种封闭场景，能做到 90%。
3. **天花板**在语义层：真正的解是向量检索（embedding）或混合检索（BM25 + 向量），这也正是 PowerContext 配置 Embedding 后提供的路径。

> 这三条构成了设计文档的核心论证链：**先量化问题，再给分层解法，最后说明每层的边界**。

## 五、复现方式

```powershell
cd ob-competition\experiments

# A/B 组（开发集）
..\.venv\Scripts\python.exe evaluate.py

# C 组（留出集）
..\.venv\Scripts\python.exe evaluate.py --cases cases_holdout.jsonl --out results_holdout.csv

# D 组（同义词集）
..\.venv\Scripts\python.exe evaluate.py --cases cases_synonym.jsonl --out results_synonym.csv

# E 组（同义词集 + 查询改写）
..\.venv\Scripts\python.exe evaluate.py --cases cases_synonym.jsonl --expand --out results_synonym_expanded.csv

# 规模测试（会新建一个专用 Scope，跑到 400 条）
..\.venv\Scripts\python.exe stress.py
```

每次运行都会覆盖写出 CSV，答辩时可当场重跑。
